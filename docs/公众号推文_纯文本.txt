忘了生信工具的命令怎么写？这个 TBtools 插件帮你把 conda 工具变成"填表就能跑"

写在前面：如果你在 WSL 或 Linux 虚拟机里用 conda 装了一堆生信工具，
却总在"这个参数到底怎么写"上卡住 —— 这篇是写给你的。

---

你是不是也这样

在 WSL（或 Linux 虚拟机）里用 conda 装了几十个生信工具。

真要用的时候：

- 先 conda activate 切环境
- 再想命令怎么写、参数叫什么
- 想不起来 → --help 翻半天 → 对着帮助文档理参数
- 好不容易拼出来，还得复制粘贴到终端

工具是装好了，用起来还是费劲。

因为"装好"和"用得顺"之间，隔着一层命令行。

---

这个插件就是干这个的

BioEnv Caller 是一个 TBtools 插件，它把 conda 里的工具变成可以填表的界面：

1. 自动找到所有 conda 虚拟环境
2. 列出每个环境里你装的工具（不含它们带进来的依赖）
3. 读取工具的帮助文档，自动生成参数填写界面
4. 你填好参数，点运行，插件替你执行
5. 输出实时显示在 TBtools 窗口里

它是通用的 —— 不认识任何具体工具的名字。装了什么工具，它就支持什么。

第一次装好插件、配好环境后，记得手动点一次「扫描 conda 环境」。

第一步：把参数类型定下来

这是最该花时间、但只需花一次的一步。

每个工具的帮助文档格式都不一样，参数类型没法100%可靠地自动判断。
插件会尽量推断，推断不出来的一律当普通文本。

所以第一次用某个工具时，进「编辑参数」面板把类型定下来 ——
定一次就记住了，下次打开直接用。

【图 2：编辑参数面板（放 g2-editor.png）】

这个面板能干四件事：

- 改参数类型 —— 决定它是文本框、下拉框还是勾选框
- 添加参数 —— 帮助文档里没解析出来的，自己加
- 删除参数 —— 解析错了的，一键删掉
- 一键还原 —— 删错了也没关系，随时恢复

还有一个专门解决位置参数的技巧：
参数名用「<」括起来（如 <参数名），它就不会被写进命令行里。

常见的类型，该怎么选

🟦 InFilePath —— 要一个输入文件。填 Windows 路径即可，插件自动转成 WSL 路径并复制过去。

🟦 PasteAsInFilePath —— 也是输入文件，但你手动粘贴路径（不自动复制）。

🟦 OutFilePath —— 要一个输出文件，自动转成 WSL 路径。

🟦 TextAsOutFilePath —— 要输出文件，但只填文件名就行，目录插件补全。

🟦 DirectoryPath —— 要一个目录。

🟦 FilePathList —— 要多个文件，用英文逗号分隔。

🟦 FilePathListInFile —— 要多个文件，但写在清单文件里（这里填那个清单文件）。

🟦 Choice —— 从几个固定值里选一个（变下拉框）。

🟦 CheckBox —— 一个不带值的开关（变勾选框）。

🟦 number —— 只要数字（变数字框，带上下箭头）。

🟦 Text —— 普通文本，原样传给工具。拿不准就选它，不会出错。

🟦 None —— 不显示这个参数。

💡 最常混的四个路径类型：
文件在 Windows 上、想让插件自动复制 → InFilePath
文件已经在 WSL 里 → PasteAsInFilePath
要生成的文件 → OutFilePath
只给前缀、目录插件补 → TextAsOutFilePath

第二步：连上你的 WSL 或 Linux 虚拟机

用 WSL 的话

点「扫描 conda 环境」就行，不用配任何连接信息。

用 Linux 虚拟机的话

选「Linux 虚拟机」后会弹出配置窗口：

【图 3：虚拟机连接配置（放 g3-vm.png）】

一共 4 步。

第 1 步：先拿到「主机 / IP」和「端口」

看虚拟机在哪里、网卡是什么模式：

▎虚拟机就装在这台电脑上

- 桥接 → 填虚拟机的真实 IP（虚拟机里 ip addr 查），端口 22，不用额外配置
- NAT（VMware 默认）→ 填 127.0.0.1，端口 2222，但必须先配端口转发：
  VMware →「编辑 → 虚拟网络编辑器 → VMnet8 → NAT 设置 → 添加」，
  加一条 主机端口 2222 → 虚拟机 IP 的 22
- 仅主机 → 填 VMnet1 网段里的虚拟机 IP，端口 22

⚠️ NAT 最容易踩坑：不配端口转发就一定连不上，改填虚拟机的内网 IP 也没用。

▎虚拟机在别的地方

- 同一局域网的另一台机器 → 填那台机器的 IP，端口 22
- 不同网段 / 外网 → 填公网 IP + 映射出来的端口（路由器上做端口映射）
- 推荐做法：两台电脑都装 Tailscale / ZeroTier 之类的组网工具，进同一个虚拟局域网，
  然后按「本机」那张表填

第 2 步：在插件里填字段

- 主机 / IP → 第 1 步查到的地址
- 端口 → 第 1 步查到的端口
- 用户名 → 建虚拟机时设的那个 Linux 用户名
- 密钥路径 → 你的私钥文件（还没有就先做第 3 步）
- 配置名称 → 给这套配置起个名字

其他可以不填。

第 3 步：生成密钥并装到虚拟机上（第一次必须做）

为什么必须做？插件连虚拟机用的是 SSH，而且不允许任何交互（它不会弹密码框让你输）。
它靠「私钥 + 虚拟机上的公钥」来验证身份 ——
虚拟机上没有配对的公钥，就一定连不上。

1. 在配置窗口点「生成密钥」，生成一对密钥
2. 把生成的私钥路径填进「密钥路径」
3. 把公钥发给虚拟机：在 PowerShell 里执行下面这条命令，会提示输密码

powershell
type $env:USERPROFILE\.ssh\vm_key.pub | ssh 用户名@主机 -p 端口 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"

4. 回到插件点「测试连接」，看「连接结果」是否成功

⚠️ 插件里那个「复制公钥到远端」按钮，第一次用不了 ——
它自己也不弹密码框，只适用于"已经能免密连上"的情况。第一次请用上面那条命令。

第 4 步：保存配置

测试连接成功后点「保存配置」，起个名字 ——
下次在「已存配置」里选一份、点「载入」就填回来了。多台虚拟机就存多份。

连不上怎么办

先看「连接结果」那一页，再对照：

- 连不上 → 地址错、虚拟机没开机、网络不通、NAT 没配端口转发
  先在 Windows 上 ping 主机，再 ssh 用户名@主机 -p 端口 试一次
- 提示端口被拒绝 → 主机通，但 sshd 没在听：
  虚拟机里执行 sudo apt install openssh-server && sudo systemctl enable --now ssh
- 要密码 / 认证失败 → 公钥还没装到虚拟机上，回到第 3 步
- 连上了但没有 conda → 虚拟机里 conda --version 确认一下
- 还没扫过这个目标 → 换了主机 / 用户 / 端口之后，点一次「扫描环境」
