# 装了工具却总想不起命令？这个 TBtools 插件帮你把 conda 环境"变成一张表"

> 如果你在 WSL 或 Linux 虚拟机里用 conda 装了一堆生信工具，却总卡在"参数到底怎么写"上 —— 这篇是写给你的。

---

## 一、你是不是也这样

在 WSL（适用于 Linux 的 Windows 子系统）或 Linux 虚拟机里，用 conda 建了七八个环境，装了几十个生信工具。

真要用的时候：

- 先 `conda activate` 切到对应环境
- 再回忆命令怎么写、参数叫什么
- 想不起来 → `--help` 翻半天 → 对着帮助文档一条条理参数
- 好不容易拼出来，还要复制粘贴到终端
- 跑完想复现上次的参数？早就忘了

**工具是装好了，用起来却还是费劲。**
因为"装好"和"用得顺"之间，隔着一层命令行。

## 二、这个插件就是干这个的

**BioEnv Caller** 是一个 TBtools 插件，它把 conda 里的工具**变成可以填表的界面**：

1. 自动找到所有 conda 虚拟环境
2. 列出每个环境里**你装的工具**（不含它们带进来的依赖）
3. 读取工具的帮助文档，**自动生成参数填写界面**
4. 你填好参数，点运行，插件替你执行
5. 输出实时显示在 TBtools 窗口里

**它是通用的** —— 不认识任何具体工具的名字。你装什么，它就支持什么；装了新工具，重新扫描一次就能看到。

> ⚠️ **第一次装好插件、配好环境后，一定要手动点一次「扫描 conda 环境」。**

【图 2：工具树（02-tree.png）】

左栏就是扫描结果：按环境分组，点环境展开、点工具名，右边立刻出参数界面。
**列表里只显示工具，不显示依赖** —— 装了 orthofinder 时 conda 会连带装 python，但列表里只会有 orthofinder。

## 三、核心：把参数类型定下来（只需一次）

每个工具的帮助文档格式都不一样，参数类型**没法 100% 可靠地自动判断**。
插件会尽量推断，**推断不出来的一律当普通文本**。

所以第一次用某个工具时，进「编辑参数」面板把类型定下来 —— **定一次就记住了，下次打开直接用。**

【图 3：编辑参数面板（g2-editor.png）】

这个面板能解决四类问题：

- **改参数类型** —— 决定它是文本框、下拉框还是勾选框
- **添加参数** —— 帮助文档里没解析出来的，自己加（点「添加参数」会弹出小窗，填名称和说明即可）
- **删除参数** —— 解析错了的，一键删掉（可恢复 / 不可恢复两种）
- **一键还原** —— 删错了也别慌，点「重置此工具」恢复原样

还有个专门解决**位置参数**的技巧：
**参数名用「<>」括起来**（例如 `<参数名>`），它就不会被写进命令行里 ✓

【图 4：参数区（03-options.png）】

### 参数类型对照表

| 类型 | 用途 | 长什么样 |
|---|---|---|
| InFilePath | 要一个**输入文件**（填 Windows 路径，插件自动转成 WSL 路径并复制过去） | 文本框 + 浏览按钮 |
| PasteAsInFilePath | 要输入文件，但**你手动粘贴路径**（不自动复制） | 文本框 |
| OutFilePath | 要一个**输出文件** | 文本框 + 浏览按钮 |
| TextAsOutFilePath | 要输出文件，但**只填文件名**（目录插件补全） | 文本框 |
| DirectoryPath | 要一个**目录** | 文本框 + 浏览按钮 |
| FilePathList | 要**多个文件**（英文逗号分隔） | 文本框 |
| FilePathListInFile | 要多个文件，**写在清单文件里** | 文本框 + 浏览按钮 |
| Choice | 从几个**固定值**里选 | 下拉框 |
| CheckBox | 一个**不带值的开关** | 勾选框 |
| number | 只要**数字** | 数字框（带上下箭头） |
| Text | **普通文本**，原样传入 —— **拿不准就选它** | 文本框 |
| None | **不显示**这个参数 | 无控件 |

> 💡 **最容易混的四个路径类型**：
> 文件在 Windows 上、想让插件自动复制 → **InFilePath**
> 文件已经在 WSL 里 → **PasteAsInFilePath**
> 要生成的文件 → **OutFilePath**
> 只给前缀、目录插件补 → **TextAsOutFilePath**

### 参数太多？打开独立窗口填

【图 5：在新窗口中打开（16-options-window.png）】

## 四、第二步：连上你的 WSL 或 Linux 虚拟机

### 用 WSL 的话

打开插件 → 点「**扫描 conda 环境**」即可，**不用配任何连接信息**。

### 用 Linux 虚拟机的话

【图 7：虚拟机连接配置（g3-vm.png）】

插件里选「Linux 虚拟机」后，会弹出这个窗口。按四步走：

#### 第 1 步：先拿到「主机 / IP」和「端口」

看虚拟机在哪、网卡是什么模式：

**虚拟机就装在这台电脑上**

| 网络模式 | 主机 / IP | 端口 | 还要做什么 |
|---|---|---|---|
| **桥接** | 虚拟机的**真实 IP**（虚拟机里 `ip addr` 查） | `22` | 无 |
| **NAT**（VMware 默认） | `127.0.0.1` | `2222` | **必须先配端口转发**：VMware → 编辑 → 虚拟网络编辑器 → VMnet8 → NAT 设置 → 添加：主机端口 `2222` → 虚拟机 IP 的 `22` |
| **仅主机（Host-Only）** | **VMnet1 网段**里的虚拟机 IP | `22` | 无 |

> ⚠️ **NAT 最容易踩坑**：不配端口转发就一定连不上，改填虚拟机内网 IP 也没用。

**虚拟机在别的地方（不在同一台机器 / 不在同一局域网）**

| 虚拟机在哪 | 主机 / IP | 端口 | 前提 |
|---|---|---|---|
| 同一局域网的另一台机器 | 那台机器的 IP | `22` | 对方防火墙放行 |
| 不同网段 / 外网 | 那台机器的**公网 IP** | 映射出来的端口（如 `2222`） | 路由器做端口映射 + 宿主机上配 NAT 转发 |
| 不同网段（**推荐**） | 组网后那台机器的**虚拟 IP** | `22` 或 `2222` | 两台电脑都装 Tailscale / ZeroTier，进同一网络 |

> **最省事的两种做法**：① 把虚拟机网卡设成**桥接**，它就像局域网里一台独立机器；
> ② 用**异地组网**把两台电脑拉进同一虚拟局域网，再按「本机」那张表填。

#### 第 2 步：填几个字段

| 字段 | 填什么 |
|---|---|
| **主机 / IP** | 第 1 步查到的地址 |
| **端口** | 第 1 步查到的端口 |
| **用户名** | 建虚拟机时设的那个 Linux 用户名 |
| **密钥路径** | 你的私钥文件（还没有就先做第 3 步） |
| **配置名称** | 给这套配置起个名字 |

其他可以不填。

#### 第 3 步：生成密钥并装到虚拟机上（第一次必须做）

**为什么必须做？** 插件连虚拟机用的是 SSH，而且**不允许任何交互**（它不会弹密码框让你输）。
它靠「私钥 + 虚拟机上的公钥」来验证身份 —— **虚拟机上没有配对的公钥，就一定连不上。**

1. 点「**生成密钥**」→ 生成一对密钥（**口令留空**，直接回车；设了口令插件就连不上）
2. 把生成的**私钥**路径填进「密钥路径」（**不要填 `.pub`**）
3. **把公钥发给虚拟机**：在 PowerShell 里执行下面这条命令，**会提示输密码**

```powershell
type $env:USERPROFILE\.ssh\vm_key.pub | ssh 用户名@主机 -p 端口 "mkdir -p ~/.ssh && chmod 700 ~/.ssh && cat >> ~/.ssh/authorized_keys && chmod 600 ~/.ssh/authorized_keys"
```

4. 回插件点「**测试连接**」，看结果

> ⚠️ 插件里那个「**复制公钥到远端**」按钮，**第一次用不了** —— 它自己也不弹密码框，
> 只适用于"已经能免密连上"的情况。**第一次请用上面那条命令。**

【图 8：连接结果（18-vm-result.png）】

点完「测试连接」后，切到「**连接结果**」标签页看结论：
成功、失败原因、以及探测到的**操作系统 / 内核版本 / 家目录**都在这里；失败时还会给排查建议。

【图 9：网络模式速查（19-vm-netmode.png）】

「**网络模式速查**」这一页值得收藏 —— NAT / 桥接 / 仅主机三种模式分别该填什么，它写得很清楚。

#### 第 4 步：保存配置

测试连接成功后点「**保存配置**」，起个名字 —— 下次在「已存配置」里选一份、点「载入」就填回来了。多台虚拟机就存多份。

#### 连不上怎么办

先看「**连接结果**」那一页，再对照：

| 现象 | 原因 | 解决 |
|---|---|---|
| 连不上 | 地址错、虚拟机没开机、网络不通、**NAT 没配端口转发** | 先 `ping 主机`，再 `ssh 用户名@主机 -p 端口` 试一次 |
| 提示端口被拒绝 | 主机通，但 **sshd 没在听** | 虚拟机里：`sudo apt install openssh-server && sudo systemctl enable --now ssh` |
| 要密码 / 认证失败 | **公钥还没装到虚拟机上** | 回到第 3 步，手工装一次 |
| 连上了但没有 conda | 虚拟机上没 conda，或不在登录 shell 的 PATH 里 | 虚拟机里 `conda --version` 确认 |
| 还没扫过这个目标 | 换了主机 / 用户 / 端口之后第一次 | 点一次「扫描 conda 环境」 |
